## 2. 目前功能規格

### 匯入、素材與軌道

- 從檔案總管拖入素材庫，或使用匯入按鈕；再從素材庫拖到相容軌道。同一素材可重複放置，片段有獨立 ID。
- 輸入限 MP4、MP3、WAV、PNG、JPG／JPEG；主要驗證 H.264／AAC MP4、MP3、PCM WAV。影音匯入仍依賴 Windows 媒體元件的可讀性，不能把 FFmpeg 能讀視為 UI 一定支援。
- 時長以 ffprobe 為準，避免 Windows 回報整秒而漏掉短片或尾端；圖片初次放置 5 秒，可延長。
- 可持續新增影片軌／音軌，支援排序、刪除、鎖定、音量、靜音／隱藏。同軌片段不可重疊，多軌可重疊；大量軌道並非已經過無上限效能驗收。
- 上方影片軌在前景；影片軌隱藏同時停用聲音。音軌有 MUTE 按鈕，作用於預覽及匯出，可復原且存入專案。
- 軌道可收折到 30 px 單行，仍可選取、拖曳、修剪、切割、調整 Fade，保留縮小波形與效果線。
- 素材庫、預覽、屬性區、時間軸及名稱欄保留可調尺寸；長名稱需有合理空間、換行或捲動，避免被工具列擠到不可操作。

### 基本編輯與操作

- 拖片段中央移動、頭尾修剪；吸附片段邊界、零點與播放頭，提供對齊線及目標文字。
- Ctrl 點選／框選多選，Ctrl+A 全選；複製、剪下、貼上、複製至尾端、刪除及同軌波紋刪除。
- 影片可分離音訊並連動，原影片的來源聲音停用以避免重複混音；移動、修剪、切割、刪除同步處理連動夥伴。
- 群組跨軌依影片／音訊各自的軌道順序映射，保留相對時間；缺少目標軌、鎖定、重疊或破壞連動時整批拒絕，不部分套用。
- 最多 100 步 Undo／Redo；一次拖曳或批次修改只記一次復原。選取、縮放、定位、收折不增加編輯歷史。
- Ctrl+滾輪以游標時間為中心縮放；最小可讓完整內容只占可視軌道寬度 25%，極短專案可更小。Shift+滾輪水平捲動，中鍵拖曳平移。
- 拖曳按住 Shift 將位移靈敏度降為 1/10，切換 Shift 不跳點；仍遵守專案幀率。控制點感應區加大、靠近高亮、游標旁顯示數值。

### Fade

- 淡入／淡出可輸入長度、拖曳把手、右鍵快速設定或批次套用；可儲存常用淡入與淡出預設。
- 五種預設：線性、慢進、慢出、平滑 S、等功率。自訂曲線的兩個強度值可調，時間控制點固定在 1/3、2/3，並非自由拖拉的完整貝茲編輯器。
- 左鍵仍按住時，曲線與金色控制點即時變化；放開才提交專案與更新實際效果。Esc／失去擷取取消候選。
- 可設定獨立音訊 Fade；畫面淡化分透明淡化與淡黑。透明露出下層，淡黑保留前景遮蓋。
- 在 Fade 內切割，兩段保留原曲線區間；不能重新從完整曲線起點播放。手動改長度／曲線則建立新的完整區間。

### 預覽、存檔與匯出

- 空白鍵播放／暫停，時間尺及預覽滑桿定位；準備中可更新待播意圖。定位／停止不應丟棄仍可重用的預載，明確取消或內容改變才取消舊工作。
- 接點試聽播放頭前後各 2 秒，可循環；純音訊用取樣級停止位置，影片停止依 UI 計時器。手動定位退出試聽範圍。
- `.cutmaker` 為 JSON 專案，儲存素材引用與編輯決策，不內嵌媒體。支援相對路徑、原子存檔、遺失素材標示與重新連結。
- 未存變更每 30 秒另存復原資料；不覆蓋使用者專案，也不復原其他仍活動視窗的工作。換專案清除本次歷史與內部剪貼簿。
- 已存專案按路徑記憶面板、縮放、捲動、播放頭與收折；這些存於本機側錄檔，不是媒體編輯資料。
- 匯出 MP4（H.264＋AAC）或 MP3；MP3／AAC 位元率 128／192／256／320 kbps。影片三種品質，尺寸提供橫向 1080p／720p、直向 1080p、方形 1080p，幀率 24／25／30／60。
- 可匯出全時間軸或輸入指定起訖秒數，包含空白／靜音；已存在數值範圍匯出，尚無時間尺拖拉範圍的完整介面。
- 畫面尺寸／幀率存入專案；品質、位元率、目的目錄及格式存偏好；輸出起訖範圍是目前專案工作階段狀態。
- 匯出使用啟動當下快照，編碼中可繼續編輯。成功才原子替換目的檔，取消／失敗保留既有目的檔，禁止覆蓋來源及目前專案。成功後可開啟匯出位置。

## 4. 性能架構與不可破壞的設計

### 音訊連續性最優先

使用者明確要求切割不能造成任何接點斷音。「每個片段各自建立播放器」或「各段獨立重取樣再拼接」都可能重引入問題。來源共用解碼，使用一致的來源到時間軸取樣映射；切割不新增空白、重複取樣或自動淡化。

純音訊流程：來源 → 48 kHz 立體聲 float64 磁碟 PCM → `AudioTimelinePreview` 按需讀取與混音 → `PcmAudioDevice` 原生 WinMM PCM16 輸出。四個 40 ms 區塊，以裝置取樣時鐘推進播放頭，不產生整首混音 WAV、不經 MediaElement。

超過 300 秒且容量足夠的來源可走漸進解碼，播放位置附近資料就緒後開始；仍從來源零點解碼以保留重取樣相位，並非直接跳到任意深處開始解碼。資料未就緒用 `AudioBufferPendingException` 暫停裝置時鐘；不能把缺資料當靜音提交。完成才原子發布快取，取消不得發布半檔。

純音訊播放中的音量／MUTE 沿用混音器和裝置，240 個取樣（5 ms）增益斜坡；已排隊區塊造成約 160 ms 內的控制延遲。來源版本在準備時固定，來源被外部改動不能繼續套用舊 PCM。其他結構／效果修改可能重建混音計畫，但應重用來源解碼。

### 影片預覽與區間重用

`VideoRegionPreview` 將畫面切成約 10 秒、與幀率對齊的快取區間，編輯只重算受影響區間；最後搭配一次完整連續音訊渲染／編碼合併為單一 MP4，使用一個 WPF MediaElement 播放。**區間是渲染快取單位，不是播放中切換檔案的單位。**

預覽最高寬 480／960／1280，最高 30 fps；可選為至少 128 MiB 的影片建立低解析度代理。代理僅替換預覽畫面來源，音訊與正式匯出仍用原素材。首次代理、首次全片預覽、音訊重算和合併仍需時間，未實作即時逐軌影片合成。

拖曳定位採約 110 ms 合併等待後產生單張合成畫面；舊請求可取消。非同步結果必須檢查專案／預覽版本和請求序號，不能在換專案、復原或來源更動後發布舊結果。

### 時間軸、波形與背景工作

- `TimelineTrackRow` 維持穩定容器；繪圖快取靜態圖層，播放頭與互動覆蓋層分開更新，避免每次播放頭移動都重排文字和波形。
- 同軌排序且不重疊，使水平可視片段可二分搜尋；不能在允許重疊後仍假設這個條件成立。這不等於所有軌道都已做垂直虛擬化。
- 全素材概覽波形 1024 bins；放大後可載入來源局部 2048 bins，必須跟隨 `SourceIn` 對齊。波形表示來源聲音，不包含 Gain／Fade。
- 背景概覽工作同時放行一個；待處理工作讓位給互動／前景準備，已啟動的可選解碼程序降低優先權。不要讓波形重算卡住播放或滑鼠。

### 快取與狀態持久化

- `ManagedMediaCache` 僅管理明確資料夾中的雜湊命名生成物：`audio-preview`、`media-visuals`、`video-regions`、`video-proxies`。
- 使用中的檔案以 lease 防刪；共用容量預設 4 GiB，可設 1–32 GiB，屬軟上限。漸進來源預留容量，避免同程序多來源各自忽略正在載入的需求。
- 額外存在工作階段完整影片預覽：最多四份、512 MiB 軟上限，允許一份較大現用檔；另有最多合計 2 GiB 的私有來源使用範圍暫存。不要宣稱設定值涵蓋所有暫存磁碟用量。
- 快取身份包含來源路徑、大小、修改時間及相關設定；音訊另納入解碼器身份。這不是每次都完整雜湊原始媒體內容。
- 官方腳本設定 `CUTMAKER_DATA_DIR=專案/runtime`；完整測試用 `runtime/verification`。未設定環境變數直接執行則使用 `%LOCALAPPDATA%/CutMaker`。
- `preferences.json` 保存偏好，`layout.json` 保存通用版面，`project-views/<專案完整路徑雜湊>.json` 保存個別已存專案的視圖。移動專案路徑會改變視圖 key。

## 5. 曾發生的問題與回歸重點

1. **移動時間尺後 Space 失效**：不只是焦點；TSF／IME 可能包裝成 `Key.ImeProcessed`。時間尺、軌道及預覽操作區停用 IME，文字欄位保留；輸入路由解析 SystemKey／ImeProcessedKey，並清理放開後殘留的拖曳狀態。用 `ImeHotkeySmokeChecks`／`TransportSmokeChecks` 回歸。
2. **音訊預覽長時間緩衝或 timeout**：曾在新程序重現長 PCM WAV 配合 WPF ScrubbingEnabled 等不到 MediaOpened。純音訊已繞開此路徑，不能只改 Play／Pause 順序就退回 MediaElement。
3. **切割接點不連續**：保留 `AudioSampleClock`、共用重取樣和 Fade 區間。以切前／切後完整解碼取樣比較驗證，不能只靠聽感或輸出時長。
4. **Fade 直到放開才更新**：候選顯示必須在拖曳中繪製，不能每個 MouseMove 提交歷史或重建影音；正常與收折軌都測。
5. **縮放過早碰到下限**：最小值必須依內容時長與可視寬度計算，保留 25% 需求與游標時間錨定。
6. **非同步舊結果／檔案保護**：取消、換專案、來源替換與關閉都要防止舊結果回寫；FFmpeg 用 ArgumentList，不組 shell 指令；輸出採唯一暫存檔及成功後替換。

## 6. 工具鏈、建置與驗證交付流程

已安裝在專案內的工具紀錄：.NET SDK 10.0.401、Windows Desktop Runtime 10.0.12、FFmpeg／ffprobe 9.0.2；這是本地工具基準，不代表外部最新版本。固定下載與雜湊詳見 DEPENDENCIES 及 setup 腳本。現有環境不必重裝，不要加系統解碼器包或修改系統 PATH。

```powershell
Set-Location -LiteralPath 'I:\Codex\工具型\CutMaker'
git status --short
git log -5 --oneline
# 建置與執行；腳本選擇專案本地 SDK／FFmpeg
& '.\scripts\build.ps1'
& '.\scripts\run.ps1'
# 改動核心、預覽、匯出或版面後執行完整驗證
& '.\scripts\verify.ps1'
```

新機缺工具才執行 `scripts/setup.ps1`、`scripts/setup-ffmpeg.ps1`，下載後依腳本驗證。使用者啟動入口為根目錄 `啟動CutMaker.cmd`。不要在正在進行的驗證程序尚未結束時重建同一份 EXE。

驗證由三部分組成：`tests/CutMaker.Core.Checks`、App 內的離屏 WPF／原生音訊 smoke checks、`tests/CutMaker.Render.Checks` 的真實 FFmpeg 渲染比較。測試不是單純 UI 截圖：會驗證來源雜湊、存檔重開、輸出時長、像素、解碼音訊、取消與目的檔保護。

## 7. 已知限制與下一步候選

- 純音訊有即時音量／MUTE；含影片的專案仍須更新預覽。影片區間命中不代表音訊及最後合併無成本。
- 深處冷定位仍可能等解碼追上；極長來源、容量不足或快取淘汰後可能重新準備。原生混音用 95% 峰值截限，過載時與匯出前視限制器聽感可能不同。
- 尚無真人長片、大量軌道、不同音效裝置、所有編碼／可變幀率素材的完整驗收；先以實際案例量測再宣稱性能提升。
- 操作 P2 尚未全面實作：例如 Solo／音量表、時間尺範圍編輯、素材庫搜尋、智慧新增相容軌道、更多直接音量控制。現有數值範圍匯出及音量設定不能誤列為完全不存在。
- 尚無即時影片合成、完整代理管理介面、逐格縮圖帶、全軌波紋、自由貝茲控制、交叉轉場、字幕、變速、降噪、安裝包／完整可攜式發行。
- 其他文件含歷史段落：例如「固定 1024 波形」「畫質／位元率只存工作階段」「收折只存本次」「尚無代理」。0.8 已增加局部 2048 波形、偏好持久化、專案視圖與選用代理；接手時以程式和本文件對應版本為準，不按舊描述退回功能。
